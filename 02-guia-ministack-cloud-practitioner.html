Guía Práctica con MiniStack

Preparación para AWS Certified Cloud Practitioner (CLF-C02) — Ejemplos resueltos básicos (CRUD y más)

Requisito: Tener Docker instalado y MiniStack corriendo en localhost:4566. Todos los ejemplos usan credenciales ficticias (test/test) y región us-east-1.

0. Configuración Inicial

# Iniciar MiniStack
docker run -d --name ministack -p 4566:4566 ministackorg/ministack

# Variables de entorno recomendadas (opcional)
export AWS_ACCESS_KEY_ID=test
export AWS_SECRET_ACCESS_KEY=test
export AWS_DEFAULT_REGION=us-east-1

# Alias útil (agrega a tu .bashrc o .zshrc)
alias awslocal='aws --endpoint-url=http://localhost:4566'

# Probar
awslocal sts get-caller-identity

A partir de ahora usaré awslocal en los ejemplos. Si no quieres el alias, usa aws --endpoint-url=http://localhost:4566.

1. Amazon S3 — Object Storage

Almacenamiento de objetos. Ideal para archivos, backups, sitios estáticos, data lakes.

CRUD básico

# CREATE - Crear bucket
awslocal s3 mb s3://mi-bucket-practica

# CREATE - Subir objeto
echo "Hola MiniStack desde S3" > hello.txt
awslocal s3 cp hello.txt s3://mi-bucket-practica/hello.txt

# READ - Listar buckets y objetos
awslocal s3 ls
awslocal s3 ls s3://mi-bucket-practica/

# READ - Descargar objeto
awslocal s3 cp s3://mi-bucket-practica/hello.txt ./descargado.txt
cat descargado.txt

# UPDATE - Subir versión nueva (sobrescribe)
echo "Contenido actualizado" > hello.txt
awslocal s3 cp hello.txt s3://mi-bucket-practica/hello.txt

# DELETE - Eliminar objeto y bucket
awslocal s3 rm s3://mi-bucket-practica/hello.txt
awslocal s3 rb s3://mi-bucket-practica

2. Amazon DynamoDB — NoSQL

Base de datos NoSQL de clave-valor y documentos. Alta escala y baja latencia.

# CREATE - Crear tabla
awslocal dynamodb create-table \
  --table-name Usuarios \
  --attribute-definitions AttributeName=userId,AttributeType=S \
  --key-schema AttributeName=userId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST

# CREATE - Insertar item
awslocal dynamodb put-item \
  --table-name Usuarios \
  --item '{"userId":{"S":"u001"},"nombre":{"S":"David"},"edad":{"N":"30"}}'

# READ - Obtener item
awslocal dynamodb get-item \
  --table-name Usuarios \
  --key '{"userId":{"S":"u001"}}'

# READ - Scan (todos los items)
awslocal dynamodb scan --table-name Usuarios

# UPDATE - Actualizar item
awslocal dynamodb update-item \
  --table-name Usuarios \
  --key '{"userId":{"S":"u001"}}' \
  --update-expression "SET edad = :e" \
  --expression-attribute-values '{":e":{"N":"31"}}'

# DELETE - Eliminar item
awslocal dynamodb delete-item \
  --table-name Usuarios \
  --key '{"userId":{"S":"u001"}}'

# DELETE - Eliminar tabla
awslocal dynamodb delete-table --table-name Usuarios

3. Amazon RDS — Bases de Datos Relacionales

MiniStack levanta un contenedor real de Postgres o MySQL.

# CREATE - Instancia Postgres
awslocal rds create-db-instance \
  --db-instance-identifier mi-postgres \
  --db-instance-class db.t3.micro \
  --engine postgres \
  --master-username admin \
  --master-user-password Secret123! \
  --allocated-storage 20

# Esperar a que esté disponible (puede tardar un poco)
awslocal rds describe-db-instances --db-instance-identifier mi-postgres

# Conectar (cuando esté ready) — usa el puerto que muestre MiniStack (normalmente 15432)
# psql -h localhost -p 15432 -U admin -d postgres
# Contraseña: Secret123!

# DELETE
awslocal rds delete-db-instance \
  --db-instance-identifier mi-postgres \
  --skip-final-snapshot

Nota: MiniStack inicia un contenedor Docker real de Postgres. Revisa los logs del contenedor de MiniStack para ver el puerto exacto.

4. AWS Lambda — Serverless

Ejecuta código sin administrar servidores. MiniStack ejecuta Python real.

# Crear archivo de función
cat > handler.py << 'EOF'
def handler(event, context):
    name = event.get("name", "Mundo")
    return {
        "statusCode": 200,
        "body": f"Hola {name} desde Lambda en MiniStack!"
    }
EOF

# Empaquetar
zip function.zip handler.py

# CREATE - Crear función
awslocal lambda create-function \
  --function-name MiFuncion \
  --runtime python3.12 \
  --handler handler.handler \
  --role arn:aws:iam::000000000000:role/lambda-role \
  --zip-file fileb://function.zip

# INVOKE
awslocal lambda invoke \
  --function-name MiFuncion \
  --payload '{"name":"David"}' \
  response.json

cat response.json

# UPDATE - Actualizar código (vuelve a zippear y update-function-code)
# DELETE
awslocal lambda delete-function --function-name MiFuncion

5. Amazon SQS + SNS — Mensajería

# === SQS ===
# CREATE
QUEUE_URL=$(awslocal sqs create-queue --queue-name mi-cola --output text --query QueueUrl)
echo $QUEUE_URL

# SEND
awslocal sqs send-message --queue-url $QUEUE_URL --message-body "Mensaje de prueba"

# RECEIVE
awslocal sqs receive-message --queue-url $QUEUE_URL

# DELETE message (usa el ReceiptHandle del receive)
# awslocal sqs delete-message --queue-url $QUEUE_URL --receipt-handle RECEIPT_HANDLE

# === SNS ===
TOPIC_ARN=$(awslocal sns create-topic --name mi-topico --output text --query TopicArn)

# Suscribir SQS a SNS (fan-out)
awslocal sns subscribe \
  --topic-arn $TOPIC_ARN \
  --protocol sqs \
  --notification-endpoint $(awslocal sqs get-queue-attributes --queue-url $QUEUE_URL --attribute-names QueueArn --output text --query Attributes.QueueArn)

# Publicar
awslocal sns publish --topic-arn $TOPIC_ARN --message "Hola desde SNS!"

# Limpiar
awslocal sqs delete-queue --queue-url $QUEUE_URL
awslocal sns delete-topic --topic-arn $TOPIC_ARN

6. EventBridge + Step Functions

# === EventBridge ===
# Crear bus (opcional, default funciona)
awslocal events create-event-bus --name mi-bus

# Crear regla simple (ejemplo: log a CloudWatch)
# En la práctica combina con Lambda o SNS como target

# === Step Functions ===
# Definición simple de máquina de estados
cat > definition.json << 'EOF'
{
  "Comment": "Ejemplo simple",
  "StartAt": "HelloWorld",
  "States": {
    "HelloWorld": {
      "Type": "Pass",
      "Result": "Hola desde Step Functions",
      "End": true
    }
  }
}
EOF

# CREATE
awslocal stepfunctions create-state-machine \
  --name MiMaquina \
  --definition file://definition.json \
  --role-arn arn:aws:iam::000000000000:role/step-functions-role

# START execution
awslocal stepfunctions start-execution \
  --state-machine-arn arn:aws:states:us-east-1:000000000000:stateMachine:MiMaquina \
  --input '{"key":"value"}'

9. Amazon ECS — Contenedores

MiniStack ejecuta contenedores Docker reales.

# CREATE cluster
awslocal ecs create-cluster --cluster-name mi-cluster

# Registrar task definition (ejemplo simple)
awslocal ecs register-task-definition \
  --family mi-tarea \
  --container-definitions '[{
    "name": "nginx",
    "image": "nginx:alpine",
    "memory": 128,
    "portMappings": [{"containerPort": 80}]
  }]'

# Run task
awslocal ecs run-task \
  --cluster mi-cluster \
  --task-definition mi-tarea \
  --launch-type EC2

# Listar
awslocal ecs list-tasks --cluster mi-cluster
awslocal ecs list-clusters

10. Amazon CloudWatch

# Put custom metric
awslocal cloudwatch put-metric-data \
  --namespace MiApp \
  --metric-name RequestCount \
  --value 42 \
  --unit Count

# Get metric statistics
awslocal cloudwatch get-metric-statistics \
  --namespace MiApp \
  --metric-name RequestCount \
  --start-time 2026-01-01T00:00:00Z \
  --end-time 2026-12-31T23:59:59Z \
  --period 3600 \
  --statistics Sum

awslocal logs create-log-stream --log-group-name /mi-app/logs --log-stream-name stream1

14. EC2 + VPC (básico)

MiniStack permite crear VPCs, subnets y security groups (nivel de API).

# CREATE VPC
VPC_ID=$(awslocal ec2 create-vpc --cidr-block 10.0.0.0/16 --output text --query Vpc.VpcId)
echo $VPC_ID

# CREATE Subnet
awslocal ec2 create-subnet \
  --vpc-id $VPC_ID \
  --cidr-block 10.0.1.0/24 \
  --availability-zone us-east-1a

# CREATE Security Group
awslocal ec2 create-security-group \
  --group-name mi-sg \
  --description "Security Group de practica" \
  --vpc-id $VPC_ID

# Listar
awslocal ec2 describe-vpcs
awslocal ec2 describe-subnets
awslocal ec2 describe-security-groups

Nota: el networking real (routing de paquetes) no se simula completamente en MiniStack. Sirve para familiarizarse con las APIs y conceptos.
