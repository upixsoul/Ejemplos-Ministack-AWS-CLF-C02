1. ¿Qué es MiniStack?

MiniStack es un emulador local de AWS de código abierto (licencia MIT) que corre en un solo contenedor Docker. Es una alternativa gratuita y ligera a LocalStack, especialmente útil después de que LocalStack moviera varios servicios core a planes de pago.

  • 60+ servicios en el puerto 4566
  • Infraestructura real en RDS (Postgres/MySQL), ElastiCache (Redis) y ECS
  • Multi-account y multi-region
  • Compatible con AWS CLI, SDKs (incluyendo .NET), Terraform, CDK, Pulumi
  • Arranque en ~2 segundos y ~30 MB de RAM en idle
  • Sin cuenta, sin API key y sin telemetría
Ideal para aprender AWS, desarrollar localmente y correr pipelines de CI sin gastar dinero en la nube.

2. Instalación y configuración

Levantar MiniStack

docker run -p 4566:4566 ministackorg/ministack

También puedes instalarlo con pip install ministack && ministack.

Variables de entorno recomendadas

export AWS_ACCESS_KEY_ID=test
export AWS_SECRET_ACCESS_KEY=test
export AWS_DEFAULT_REGION=us-east-1
export AWS_ENDPOINT_URL=http://localhost:4566

Perfil de AWS CLI

aws configure --profile ministack
# Access Key ID: test
# Secret Access Key: test
# Default region: us-east-1
# Output format: json

Luego usa --profile ministack --endpoint-url http://localhost:4566 en tus comandos.

Health check: curl http://localhost:4566/_ministack/health

3. Primeros pasos con AWS CLI

# Crear bucket
aws --endpoint-url=http://localhost:4566 s3 mb s3://mi-primer-bucket

# Listar buckets
aws --endpoint-url=http://localhost:4566 s3 ls

# Subir archivo
echo "Hola MiniStack" > hola.txt
aws --endpoint-url=http://localhost:4566 s3 cp hola.txt s3://mi-primer-bucket/

# Listar contenido
aws --endpoint-url=http://localhost:4566 s3 ls s3://mi-primer-bucket/

4. Servicios core

DynamoDB

aws --endpoint-url=http://localhost:4566 dynamodb create-table \
  --table-name Usuarios \
  --attribute-definitions AttributeName=Id,AttributeType=S \
  --key-schema AttributeName=Id,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST

aws --endpoint-url=http://localhost:4566 dynamodb put-item \
  --table-name Usuarios \
  --item '{"Id":{"S":"1"},"Nombre":{"S":"Ana"},"Ciudad":{"S":"Guadalajara"}}'

aws --endpoint-url=http://localhost:4566 dynamodb scan --table-name Usuarios

SQS

aws --endpoint-url=http://localhost:4566 sqs create-queue --queue-name pedidos

# Enviar mensaje
aws --endpoint-url=http://localhost:4566 sqs send-message \
  --queue-url http://localhost:4566/000000000000/pedidos \
  --message-body "Nuevo pedido #123"

# Recibir mensaje
aws --endpoint-url=http://localhost:4566 sqs receive-message \
  --queue-url http://localhost:4566/000000000000/pedidos

SNS

aws --endpoint-url=http://localhost:4566 sns create-topic --name notificaciones
# Luego puedes suscribir una cola SQS al topic para practicar patrones pub/sub

5. Ejemplos en C# / .NET

Instala los paquetes NuGet: AWSSDK.S3, AWSSDK.DynamoDBv2, AWSSDK.SQS, etc.

S3

using Amazon.S3;
using Amazon.S3.Model;

var config = new AmazonS3Config
{
    ServiceURL = "http://localhost:4566",
    ForcePathStyle = true
};

using var s3 = new AmazonS3Client("test", "test", config);

await s3.PutBucketAsync(new PutBucketRequest { BucketName = "dotnet-bucket" });

await s3.PutObjectAsync(new PutObjectRequest
{
    BucketName = "dotnet-bucket",
    Key = "documento.txt",
    ContentBody = "Contenido desde .NET + MiniStack"
});

var list = await s3.ListObjectsV2Async(new ListObjectsV2Request { BucketName = "dotnet-bucket" });
foreach (var obj in list.S3Objects)
    Console.WriteLine(obj.Key);

DynamoDB

using Amazon.DynamoDBv2;
using Amazon.DynamoDBv2.Model;

var ddbConfig = new AmazonDynamoDBConfig { ServiceURL = "http://localhost:4566" };
using var ddb = new AmazonDynamoDBClient("test", "test", ddbConfig);

var request = new PutItemRequest
{
    TableName = "Usuarios",
    Item = new Dictionary
    {
        { "Id", new AttributeValue { S = "42" } },
        { "Nombre", new AttributeValue { S = "Carlos" } },
        { "Activo", new AttributeValue { BOOL = true } }
    }
};

await ddb.PutItemAsync(request);

6. Infraestructura real

Una de las mejores características de MiniStack: no solo simula la API, sino que levanta software real.

RDS (Postgres)

aws --endpoint-url=http://localhost:4566 rds create-db-instance \
  --db-instance-identifier mi-postgres \
  --db-instance-class db.t3.micro \
  --engine postgres \
  --master-username admin \
  --master-user-password SuperSecret123 \
  --allocated-storage 20

MiniStack inicia un contenedor real de Postgres. Luego puedes conectarte con cualquier cliente (DBeaver, pgAdmin, Npgsql desde .NET, etc.).

ElastiCache (Redis)

aws --endpoint-url=http://localhost:4566 elasticache create-cache-cluster \
  --cache-cluster-id mi-redis \
  --engine redis \
  --cache-node-type cache.t3.micro \
  --num-cache-nodes 1

7. Serverless

Puedes practicar flujos completos con Lambda, API Gateway, EventBridge y Step Functions. MiniStack ejecuta funciones Lambda (principalmente Python por defecto; también soporta otros runtimes según la versión).

Consejo: Empieza creando una Lambda simple que lea de DynamoDB o escriba en S3, y luego expónla a través de API Gateway.

8. Infrastructure as Code con Terraform

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region                      = "us-east-1"
  access_key                  = "test"
  secret_key                  = "test"
  skip_credentials_validation = true
  skip_requesting_account_id  = true
  skip_metadata_api_check     = true

  endpoints {
    s3       = "http://localhost:4566"
    dynamodb = "http://localhost:4566"
    sqs      = "http://localhost:4566"
    sns      = "http://localhost:4566"
    lambda   = "http://localhost:4566"
    iam      = "http://localhost:4566"
  }
}

resource "aws_s3_bucket" "aprendizaje" {
  bucket = "terraform-ministack-demo"
}

resource "aws_dynamodb_table" "usuarios" {
  name         = "UsuariosTerraform"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "Id"

  attribute {
    name = "Id"
    type = "S"
  }
}

Ejecuta terraform init && terraform apply apuntando a MiniStack.

10. Tips, limitaciones y comandos útiles

Comandos útiles

# Estado de salud
curl http://localhost:4566/_ministack/health

# Resetear todo el estado (borra buckets, tablas, colas, etc.)
curl -X POST http://localhost:4566/_ministack/state/reset

Limitaciones importantes

  • No hay enforcement real de políticas IAM (casi todas las llamadas tienen éxito).
  • No todos los servicios tienen cobertura del 100% de operaciones.
  • Algunas funciones avanzadas de networking, EKS o servicios muy nuevos están parciales.
  • Excelente para aprendizaje y desarrollo local; no sustituye pruebas en la nube real antes de producción.
